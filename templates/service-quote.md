# 海外服务范围与报价模板

直接复制这份结构，替换成你的真实情况后发给客户。左边是字段，中间是你需要填的内容，右边说明这一项为什么必须写清楚。

| 字段 Field | 你需要填的内容 | 为什么必须写清楚 |
|---|---|---|
| Client / 客户 | 公司全称、联系人、所在地 | 决定合同主体、币种和税务处理 |
| Problem / 要解决的问题 | 客户为什么现在愿意付费 | 范围谈不拢通常源于问题没定义清楚 |
| Scope / 包含的任务 | 逐条列出这次要做的事 | 避免交付时被追加未计价的工作 |
| Exclusions / 不包含的事项 | 明确写出不做哪些事 | 排除项比包含项更能减少争议 |
| Deliverables / 交付物 | 文件、功能、报告或服务次数 | 客户按清单验收，你也按清单交付 |
| Timeline / 各阶段日期 | 开始、中期检查、最终交付 | 让客户预期可控，便于安排自己的时间 |
| Acceptance / 验收方式 | 客户怎样算确认完成 | 没有验收标准的项目很难结项 |
| Revisions / 修改次数 | 含几轮修改，超出如何计价 | 修改次数是最常见的成本失控点 |
| Currency and fee / 货币与价格 | 币种、金额、谁承担手续费 | 手续费和汇损归属不清会让实际到账缩水 |
| Payment milestones / 付款条件 | 预付比例、尾款节点、账期 | 分阶段收款降低单笔风险 |
| Confidentiality / 保密与数据 | 客户资料如何使用、何时删除 | 涉及客户数据和账号权限时必须先约定 |
| Maintenance / 售后与维护 | 是否含维护、期限与额外费用 | 交付后的支持边界要提前说清 |

## 报价邮件示例

Subject — Proposal for [specific project]

Hi [First name],

Thanks for sharing the details. I can help with [specific problem]. The deliverables would be [A], [B], and [C], with a target completion date of [date].

My project fee is USD [amount], split into [payment milestones]. This includes [number] revisions. Anything outside the agreed scope would be quoted separately.

If this fits your needs, I can send the final scope for review.

Best,
[Your name]

## 使用这份模板时的三个提醒

- 价格是演示档位，不代表市场均价。定价要结合你的真实经验、交付成本和客户预算，不要照抄。
- 不要在合同里承诺「保证增长」「保证排名」这类你无法控制的结果。
- 涉及客户后台权限、客户数据和第三方素材时，先取得书面授权，再开始操作。

此模板是范围确认与沟通工具，不替代适用于具体交易的合同和法律意见。
